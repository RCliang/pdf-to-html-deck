# 片段产出:子代理派发模板与调度策略

页面内容由子代理并行撰写。**调度约束(实战结论):**
- 后台子代理并发上限约 **2 个**;再多会被拒("user concurrency limit exceeded")。
- 可用「2 后台 + 1 前台」三路流水线;后台完成一个立刻补一个。
- 被拒的任务直接重发即可,不损失任何东西。

## 派发前,主代理必须先亲自完成
1. `work/shell.html`(从模板复制并改标题/tokens);
2. **金标准示范页** 1 张(挑书中中等篇幅、有数字有结构图的一章,自己写,质量=全卷天花板),存 `work/fragments/`;
3. `work/SPEC.md`(= 本 skill 的 `references/design-spec.md` 复制进项目,可按书微调)。

子代理的质量来自「规范 + 金标准 + 原文」三件套,缺一发虚。

## 概念页派发模板(每组 1-3 章,产出 2-3 页)

```text
你是《书名》演示文稿的内容作者。严格执行:

1. 读规范:<项目绝对路径>/work/SPEC.md(必须完全遵守)
2. 读金标准范本:<项目绝对路径>/work/fragments/<金标准文件>.html
   (你的产出质量对齐它:结构、密度、SVG 水准、route 写法;route 节点一律 <circle cx cy> 定位,不要 transform)
3. 读章节原文:<项目绝对路径>/work/text/chNN.txt(约 pXXX-YYY)
4. 用 Write 写出 N 个片段文件:

▸ <绝对路径>/work/fragments/<名>.html
  id="…" data-part="<N>" data-crumb="PART N · CH M" data-title="≤14字"
  内容:<2-4 个主题点,列出必须覆盖的术语/数字/机制>

硬性要求:
- 只写上述文件;每文件 1 个 <section>;整页高度必须放得下:s-body 可用约 400px;
  卡片 ≤4 张、底部表格 ≤4 行(dense ≤11 行);宁可精简文字也不要溢出(overflow 会被判不合格)
- 忠实原文:数字/术语中英对照/页码来自文本,不许编造;反直觉结论放 .k-callout
- 每页必有 route band(3-5 节点)+ .fig SVG 或 .k-table 至少其一
- SVG 线条 var(--cyan),强调 var(--verm)/var(--amber);动效 draw/pop ≤6;文字 class mut/m;标注不压线条
- 禁 <style>/<script>/外部资源/emoji
- 完成后报告:每个文件路径 + 每页一句话摘要
```

要点:
- 模板必须**自包含**(绝对路径、明确产出文件清单);子代理看不到会话历史。
- 「整页放得下」要写成硬约束——子代理天然贪多,溢出是最高频返工原因。
- 大章(>60 页文本)拆 2-3 页:如 c06a/b/c;派发时把每页的主题点直接写进任务。

## 代码页派发模板

同上,但第 3 条指向含代码的章节与具体 Listing 小节,硬性要求追加:

```text
- 代码 ≤22 物理行、pre 内不留空行;忠实原书 API/参数名/默认值;
  允许重排缩进、用 ... 删无关分支、加 ①②③ 注释
- 讲解卡 3-4 张与代码序号一一对应,每张 ≤70 字
- 运行 callout(.k-callout g)单行:依赖 + 启动命令 + 预期输出
- section 加 class="slide codeslide";眉题首个标签 <span class="tag am">CODE</span>
```

## 框架页(主代理自写,不派发)
封面、总目录/航线图、各部分扉页(章列表+页码)、尾页(阅读路径/全书总览)——这些需要全局视角与全书页码信息,子代理没有,自己写。

## 分工速记
- 主代理:壳、金标准、框架页、组装、验收修复
- 子代理:概念页、代码页(每组带 SPEC+金标准+原文三件套)
